# dsh-agent-manager

[![CI](https://github.com/WatchDG/dsh-agent-manager/actions/workflows/ci.yml/badge.svg)](https://github.com/WatchDG/dsh-agent-manager/actions/workflows/ci.yml)
[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

[English](README.md) | **Русский**

Плагин менеджера агентов для [DeepSeek Harness](https://www.deepseek.com/en/harness/):
создание, просмотр, сообщения и прерывание субагентов сессии — из живой
веб-панели в шапке беседы, из команды `/agent-manager` или из инструментов
модели (`agent_manager_*`). Когда рантайм Agent Teams смонтирован на хосте,
те же поверхности дополнительно показывают состав команды и общую доску задач.

Плагин не добавляет собственного каркаса: он управляет теми же продолжаемыми
субагентами, которыми уже владеет Harness (провайдеры spawn/fork), поэтому
созданные агенты получают весь механизм сессии — персистентность, холодное
возобновление, последующие ходы — бесплатно.

## Возможности

- **Персистентные определения агентов** — «Настройки → Агенты» хранит
  устойчивый реестр (глобальный для профиля, `<workspace>/.agent-manager/state.json`)
  определений агентов: имя, описание, базовый промпт, бэкенд и политика
  модели. Создание, изменение и удаление прямо там; определения переживают
  перезапуск и доступны всем сессиям.
- **Выбор модели для агента** — определение либо наследует модель сессии
  спавна, либо позволяет координатору выбрать точный маршрут из списка
  распределения, либо фиксирует собственные provider/model. Агент с
  фиксированной моделью всегда использует её; агент в режиме auto при
  отсутствии выбора наследует модель сессии.
- **Спавн по задаче** — определённый агент запускается в любую сессию с
  конкретной задачей (`agent_manager_spawn`, `/agent-manager run` или блок
  спавна в настройках). Ребёнок работает с базовым промптом плюс задача в
  новой продолжаемой сессии.
- **Веб-панель** — действие «Агенты» в шапке беседы: список спавненных детей
  сессии со статусом, отправка сообщений, прерывание, копирование id.
- **Инструменты модели** — `agent_manager_list`, `agent_manager_spawn`,
  `agent_manager_list_models`, `agent_manager_message`,
  `agent_manager_interrupt`, а при наличии рантайма Agent Teams —
  `agent_manager_task_create/list/update`. Одна операция — одно поведение и в
  UI, и в инструментах.
- **Команда** — `/agent-manager` для статуса и
  `/agent-manager run [--model <provider>/<model>] <агент> | <задача>` для
  спавнa определённого агента.
- **Страница настроек** — «Настройки → Агенты»: бэкенд по умолчанию, модели
  для распределения, лимит списка, видимость действия в шапке, интервал
  автообновления, вкл/выкл инструментов — плюс реестр определений и блок
  спавнa выше.
- **Опциональная интеграция Agent Teams** — при наличии `ctx.agentTeams`
  обзор включает состав команды (лидер/участники, статус, модель) и задачи;
  имена участников становятся допустимыми целями сообщений/прерываний у лидера.

## Требования

| Требование | Детали |
|---|---|
| [DeepSeek Harness](https://www.deepseek.com/en/harness/) | 0.2.x (проверено на 0.2.1-rc.2). Используются сервисы `subagents`, `agents`, `tools`, `commands`, `systemPrompt` и `webServer`. |
| Провайдеры субагентов | Строки `subagent-spawn-in-process` / `subagent-fork-in-process` базового профиля (включены по умолчанию в web/desktop профилях). |
| Каталог моделей (опционально) | Сервис Host `llm` для списков провайдеров/моделей; без него сохранённые маршруты остаются видимыми, но новые выбираются только из объявленного каталога. |
| Политика моделей Host (опционально) | Сервис Host `subagent-model-selection`; если он включён, его разрешённые маршруты становятся списком координатора при пустом списке плагина. |
| Agent Teams (опционально) | Рантайм команд хоста (строка `agent-team`) для поверхностей состава/задач. Без него управление прямыми детьми-агентами продолжает работать. |

## Установка

Плагин — бандл текущего профиля DSH, поэтому применяется ко всем сессиям этого
профиля.

1. Откройте страницу **Plugins** в боковой панели DSH (Plugin Manager).
2. Выберите **Add plugin** / **Install bundle**, укажите этот каталог (тот,
   где лежит `package.json`), подтвердите.
3. Убедитесь, что **Agent Manager** включён в списке плагинов.

Тот же шаг доступен агенту через инструмент `plugin_manager` с
`action: install_bundle` и абсолютным путём к каталогу. DSH записывает
зависимость `link:` в `package.json` профиля; поскольку каталог связан
ссылкой, после обновления файлов плагина перезапустите DSH, чтобы Host-код
загрузился заново. Для удаления уберите бандл в Plugin Manager
(или `plugin_manager` `action: remove_bundle`).

## Использование

### Веб-панель

Откройте беседу и нажмите **Агенты** в шапке. Панель показывает дочерних
агентов, запущенных под этой сессией. Поле в строке агента отправляет
сообщение, кнопка копирования берёт id сессии, а **Прервать** останавливает
работающий ход. Панель обновляется автоматически, пока открыта.

Постоянные определения и спавн живут в «Настройки → Агенты»; панель в шапке
управляет уже запущенными детьми.

### Команда

```
/agent-manager
/agent-manager run reviewer | Проверь последний коммит.
/agent-manager run --session session-42 writer | Подготовь заметки к релизу.
/agent-manager run --model openai/gpt-5 reviewer | Проверь последний коммит.
```

Форма `run` — `<агент> | <задача>`; `--session` выбирает другую живую сессию,
а `--model provider/model` передаёт выбор координатора для агента в режиме
auto. Маршрут должен входить в список моделей для распределения. Агенты с
фиксированной моделью используют свою, агенты inherit — модель сессии, поэтому
для них `--model` игнорируется.

### Инструменты

| Инструмент | Назначение |
|---|---|
| `agent_manager_list` | Список прямых детей-агентов (живой статус), определений и состава команды/задач при наличии. |
| `agent_manager_spawn` | Спавн определённого агента с задачей; поддерживает выбор модели координатором для режима auto. |
| `agent_manager_list_models` | Список точных LLM-маршрутов, которые координатор может назначать агентам в режиме auto. |
| `agent_manager_message` | Уточняющее сообщение агенту (или участнику команды). |
| `agent_manager_interrupt` | Остановка работающего агента (или участника). |
| `agent_manager_task_create` / `agent_manager_task_list` / `agent_manager_task_update` | Общая доска задач команды (только с рантаймом Agent Teams). |

## Конфигурация

Все поля опциональны. Переопределите строку `agent-manager` в слое патча
профиля или измените на странице «Настройки → Агенты» (volatile-поля
применяются сразу).

| Поле | Тип | По умолчанию | Значение |
|---|---|---|
| `memberProvider` | `'spawn' \| 'fork'` | `'spawn'` | Бэкенд новых агентов по умолчанию. |
| `allowedModels` | `Array<{ provider, model }>` | `[]` | Точные маршруты, которые координатор может назначать агентам в режиме auto. Если пусто — используется политика Host `subagent-model-selection`, затем модель сессии. |
| `maxList` | number | `50` | Максимум строк в списках инструментов/HTTP (1–200). |
| `headerAction` | boolean | `true` | Показывать действие «Агенты» в шапке беседы. |
| `autoRefreshMs` | number | `5000` | Интервал автообновления панели (1000–60000). |
| `toolsEnabled` | boolean | `true` | Регистрировать инструменты `agent_manager_*` и секцию протокола. |

```yaml
- id: agent-manager
  config:
    memberProvider: fork
    allowedModels:
      - provider: openai
        model: gpt-5
      - provider: deepseek
        model: deepseek-flash
    maxList: 100
    headerAction: true
    autoRefreshMs: 3000
    toolsEnabled: true
```

## Границы

- **Создание/сообщения/прерывание требуют живой сессии** — её агент должен
  быть резидентным на этом хосте. Список читается из устойчивого каталога
  детей даже для закрытых сессий.
- Плагин управляет **прямыми детьми** сессии (продолжаемые, одноразовые,
  внешние). Более глубокие потомки не показываются.
- Сообщения доставляются во входящие цели; успешная отправка не означает, что
  получатель обработал сообщение. Прерывание — fire-and-return: цель может
  продолжать работу, пока не заметит сигнал отмены.
- **Agent Teams опционален.** Без рантайма команд `team` равен `null` в
  обзорах, а инструменты задач не регистрируются.
- **Выбор модели требует провайдера с поддержкой `agentOptions`.** Встроенные
  in-process провайдеры spawn/fork подходят. Список распределения берётся из
  `allowedModels`, затем из политики Host `subagent-model-selection`, затем из
  маршрута сессии. Фиксированная модель определения авторитетна, даже если
  координатор передал другой маршрут. Fork-ребёнок может работать на другом
  маршруте, но это может помешать переиспользованию префикса беседы на стороне
  провайдера.
- Состояние принадлежит сервисам сессий/субагентов Harness; плагин не хранит
  собственной персистентности и не выполняет сетевых обращений.

## Проверка

1. Страница **Plugins** показывает **Agent Manager** / **Менеджер агентов**
   и он включён.
2. Откройте беседу: в шапке есть действие **Агенты** с иконкой плагина.
   Открытие показывает пустое состояние либо существующих детей.
3. Создайте агента на странице «Настройки → Агенты» (или через
   `/agent-manager run …`, или `agent_manager_spawn`). Он появится в списке со
   статусом `running`, пока выполняется первый ход.
4. Измените агента и задайте режим `fixed`, затем запустите его: ребёнок
   покажет закреплённый маршрут в списке настроек и в результате
   `agent_manager_spawn`. Для агента `auto` выберите модель в блоке спавна или
   передайте `model_provider`/`model` в инструмент; без выбора используется
   модель сессии.
5. Отправьте сообщение агенту — он проснётся (или продолжит) и ответит.
   Используйте **Прервать** на работающем агенте.
6. `agent_manager_list` возвращает те же строки, что и панель, а
   `agent_manager_list_models` — действующие маршруты распределения.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| Нет действия в шапке | `headerAction: false`, или панель открыта на стартовой странице без беседы. |
| «The subagents service is unavailable» | В профиле нет базовых строк субагентов; переустановите/включите базовый бандл. |
| «session ... is not live» | Сессия закрыта; откройте её и повторите. |
| Создание прошло, но агента нет | Ребёнок не прошёл provisioning; посмотрите лог хоста по провайдеру субагентов. |
| Агент auto игнорирует выбранную модель | Определение зафиксировано или наследует модель — его политика важнее. Переключите его в auto. Маршрут также должен входить в действующий список распределения. |
| «no distribution models are configured» | Добавьте маршруты в «Настройки → Агенты → Модели для распределения», включите политику выбора моделей субагентов Host или не передавайте `model_provider`/`model`, чтобы использовать модель сессии. |
| Агент с фиксированной моделью не запускается | Откройте определение и задайте и провайдера, и id модели. |
| Нет состава/задач команды | Рантайм Agent Teams не смонтирован; управление прямыми детьми продолжает работать. |

## Разработка

Одна зависимость (`@deepseek-ai/schemastery` для схемы настроек) и без шага
сборки.

```bash
npm ci
npm test                 # модульные + manifest-тесты
npm run test:unit        # то же, явно
npm run pack:check       # проверка содержимого npm-пакета
```

Структура:

```
index.js              точка входа Host: экспорт apply / name / inject / Config
client.js             веб-клиент: страница «Настройки → Агенты» + панель в шапке
lib/config.js         схема Config, значения по умолчанию, нормализация, volatile snapshot
lib/agents.js         чистые преобразования каталога и проверки запросов
lib/api.js            фасад менеджера над сервисами Host subagents/agents/agentTeams
lib/tools.js          определения инструментов модели (agent_manager_*)
lib/command.js        парсер и обработчик /agent-manager
lib/plugin.js         связывание (секция + инструменты + команда + /agents/* + настройки)
test/                 node:test наборы (модульные, manifest, гейт интеграции)
```

Добавляя модуль, включите его в `files` в `package.json`; иначе manifest-тест
упадёт. См. [CONTRIBUTING.md](CONTRIBUTING.md).

## Безопасность и приватность

- Плагин не выполняет сетевых обращений и не отправляет телеметрию. Панель
  общается только с аутентифицированными маршрутами `/agents/*` хоста.
- Все операции идут через внутрипроцессный сервис субагентов Host с агентом
  вызывающей сессии в роли авторитета; нет запуска шелла и изменений
  песочницы ОС.
- Плагин не хранит собственного состояния; данные агентов живут в логах
  сессий и каталогах субагентов Harness.
